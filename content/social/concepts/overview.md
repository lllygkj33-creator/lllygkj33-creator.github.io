> 社媒联动不是"多发几个平台"，而是一条**四段链路**：从用户在平台上的真实信号出发，把平台上产生的内容变成可复用的资产，沉淀到独立站，再用 SEO 与 GEO 把它放大。**顺序不能反，缺一段就断。**

## 四段链路

```text
① 用户信号
   平台上的提问、抱怨、对比、踩坑
        ↓ 收集与归类
② 平台资产
   回答、讨论帖、视频、图钉、仓库文档
        ↓ 回流与整理
③ 独立站沉淀
   深度页面、决策表、实测数据、可引用段落
        ↓ 结构化与分发
④ SEO / GEO 放大
   搜索排名、AI 引用、品牌搜索、外链机会
```

### ① 用户信号：从问题开始，不从选题开始

真正稀缺的不是内容，是**知道用户在问什么**。平台上的原始提问比关键词工具更接近真实语言：

- 反复出现的问题 → 值得做成一页
- 有争议的问题 → 值得做成对比页
- 具体到细节的追问（"那如果 X 情况呢"）→ 最容易被漏掉，也最容易写深

**判断标准**：同一个问题出现三次以上，且现有答案互相矛盾或不够完整。

### ② 平台资产：让内容留在平台上

发完就沉的内容不算资产。资产的标准是**能被搜到、被引用、被持续访问**：

| 平台类型 | 什么样的内容会留下 | 回流方式 |
| --- | --- | --- |
| 社区与论坛 | 被高赞的回答、被反复引用的讨论帖 | 评论区补链接、个人资料页 |
| 社交平台 | 带来持续搜索的账号主页、被引用的短贴 | 主页链接、置顶 |
| 视觉与发现 | 可长期被搜到的图钉与视频 | 图钉链接、视频描述 |
| 开发者平台 | README、示例仓库、issue 里的答案 | 文档里的站点链接 |
| 创作分享 | 图纸、教程、材料清单 | 平台内的原文链接 |

### ③ 独立站沉淀：把散的经验变成一页

平台上的内容是**碎片**，独立站负责把它变成**结构**：补上口径、边界、条件与反例。

这一步是整条链路的瓶颈——**没有沉淀，前面两步只是给别人贡献热度**。

判断沉淀是否到位，问一句：**这一页解决的是平台里那个具体问题吗？有没有多出平台里没有的东西（数据、口径、边界）？**

### ④ SEO / GEO 放大：两种放大不是一回事

| | SEO 放大 | GEO 放大 |
| --- | --- | --- |
| 靠什么 | 被搜到、被点击 | 被 AI 引用、被提到 |
| 内容要求 | 页面匹配搜索意图 | 段落能独立成立、来源可核实 |
| 社媒的作用 | 品牌搜索、被发现、外链机会 | 进入语料、提高提及率 |
| 社媒链接 | 多数平台 `nofollow`，不传权重 | 不影响引用判断，语料本身才有用 |

**同一份内容要同时满足两边**：页面写得能被引用（GEO），链接指向的那一页要能被搜到（SEO）。

## 五类平台在链路里的位置

| 分组 | 平台 | 主要产出 | 在链路里的角色 |
| --- | --- | --- | --- |
| 用户与社区 | Amazon · EDM 与售后 · Discord · 官方社区 · Reddit · Facebook Groups · Quora · Stack Overflow | 真实问题、使用反馈、对比讨论 | ① 信号来源，贡献最多 |
| 社交与内容 | X · LinkedIn · YouTube · Medium · Substack | 观点扩散、长文分发、订阅关系 | ② 资产扩散，抢时效 |
| 视觉与发现 | TikTok · Pinterest | 视觉教程、清单、图钉长尾 | ② 长尾资产，持续被搜到 |
| 技术与创客 | GitHub · Docker Hub · Hugging Face · MakerWorld · Instructables | 文档、示例、图纸 | ③ 沉淀的补充形态，天然带引用 |
| 趋势与需求 | Google Trends · TikTok Trends · Pinterest Trends | 需求趋势、季节性、区域差异 | ① 信号的量化验证 |

前四组是"人和内容在哪"，最后一组是"**需求是否成立、什么时候发**"——先验证需求，再决定投不投。

## 每个平台页固定回答六个问题

1. **平台特性**：内容怎么被发现，算法与检索各看什么
2. **适合什么内容**：吃哪一类素材，不适合什么
3. **怎么和独立站配合**：哪部分留在站内，哪部分发到这里
4. **怎么导回独立站**：链接放哪、导到哪个页面、怎么区分渠道
5. **对 GEO 的作用**：会不会进 AI 语料、会不会成为引用来源
6. **红线与注意**：自我推广规则、授权范围、容易被封的操作

## 怎么开始

1. **先用趋势确认需求**，再用社区确认语言，最后才动笔
2. **只选两个平台起步**，按"用户在哪讨论""你能产出什么形态""内容会不会被搜到"三条筛
3. **站内先有母素材**：一篇有数据和结论的深度页，再拆成各平台形态
4. **记录每一层**：哪条内容去了哪个平台、导回多少次、带来什么问题
5. **按渠道复盘**：只保留有回流的平台，其余降频

> 这里讲的是联动方式，不是平台使用教程。平台规则会变，判定依据以各自官方文档为准。
