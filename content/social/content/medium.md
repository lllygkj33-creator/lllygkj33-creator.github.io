> Medium 不应该是独立站 Blog 的镜像。它更适合承载**作者视角、测评体验和观点型叙事**，借助 Medium 的读者网络和 Publication 进入新的受众；独立站则保存完整数据、测试方法、规格和长期更新。

## 平台角色

Medium 更适合：

```text
First-person Experience
+
Editorial Review
+
Opinion
+
Narrative
+
Publication Distribution
```

而独立站更适合：

```text
Reference
Data
Methodology
Evergreen Guide
Product Facts
```

两边承担不同任务。

## 测评

你可以把 Medium 重点定位成：

```text
测评与体验
```

例如独立站已经有：

```text
ZimaCube Power Consumption Test
```

Medium 不需要再复制整份测试。

可以写：

```text
I Used ZimaCube as My Main Home Server for 30 Days
```

重点变成：

```text
第一次安装
日常体验
意外问题
真正改变工作流的地方
哪些用户不适合
```

独立站则保留：

```text
测试环境
完整功耗表
温度
配置
版本
原始数据
```

## 两层内容

| Medium | 独立站 |
| --- | --- |
| What it felt like | What was measured |
| 作者判断 | 数据 |
| 使用过程 | 测试方法 |
| 取舍 | 规格 |
| 观点 | Reference |
| Narrative | Evergreen |

这可以避免完全重复。

## 原创优先

更推荐：

```text
同一素材
→ 两个不同表达
```

而不是：

```text
Website Article
→ Copy
→ Medium
```

例如：

```text
独立站：
Mini PC vs NAS for Plex

Medium：
Why I Stopped Recommending a Mini PC for Every Plex Setup
```

第二篇有作者判断和情境。

## 复制内容

如果确实需要把已经发布在独立站的文章完整同步到 Medium，Medium 当前提供 Import Tool，并会为导入文章设置指向原始来源的 canonical；作者也可以手动设置 canonical。

因此：

```text
完整转载
→ canonical 指向独立站
```

但这应该是少数情况，不应该成为核心策略。

## Publication

Medium 的一个独特玩法是：

```text
Publication
```

如果某个主题已经有成熟 Publication：

```text
AI
Programming
Self-hosted
Hardware
Productivity
```

作者可以考虑按对方投稿规则提交真正适合其读者的故事。

价值是：

```text
借别人的 Topic Audience
```

而不是：

```text
自己再建一个没人看的 Medium 镜像号
```

## 作者身份

Medium 比公司账号更适合突出：

```text
真实作者
+
真实体验
+
明确立场
```

例如：

```text
Hardware reviewer
Self-hosting enthusiast
AI practitioner
Developer
```

作者在 Medium 的内容方向最好与站内作者专长一致。

## 数据引用

Medium 测评里可以只呈现：

```text
最关键 3–5 个结果
```

然后告诉读者：

```text
完整测试方法和原始数据在独立站
```

这样链接有真实理由。

不是：

```text
Read more on our website
```

而是：

```text
Full benchmark table
Raw test conditions
Compatibility matrix
```

## 评论

Medium 的 Responses / Comments 可以继续产生：

```text
反例
追问
不同工作流
```

有价值的问题再回到独立站：

```text
更新 FAQ
补条件
增加测试
```

## 长期主题

适合 Medium 的系列：

```text
30-day review
What I learned
Why we changed
X vs Y after real use
What surprised me
What failed
```

不适合：

```text
每个产品规格页
每个 Support FAQ
每次小版本更新
```

## 不做

- 不把全部 Blog 自动同步
- 不创建大量重复内容
- 不把品牌宣传稿伪装成个人测评
- 不虚构第一人称 Experience
- 不隐藏测试缺陷
- 不只写优点
- 不把 Publication 当外链农场

## 工作流

```text
站内测试 / 用户体验
↓
找真正有故事性的角度
↓
作者第一人称重写
↓
Medium 测评 / 观点
↓
必要时提交 Publication
↓
引用站内原始数据
↓
回收评论与反例
↓
补强独立站
```

核心原则：

> **Medium 写“我为什么这样判断”，独立站保存“这个判断建立在什么证据上”。**
