> 总分 100 分，由七个固定维度加权而成。**权重不随关键词变**——换了关键词只换数据，不换算法，这样不同实例之间才可比。

## 七个维度与权重

| 维度 | 权重 | 核心问题 |
| --- | ---: | --- |
| 意图匹配 | 20% | 页面类型与答案是否匹配当前搜索结果意图 |
| 覆盖度 | 15% | 必要的问题与子问题是否覆盖 |
| 深度 | 15% | 是否比竞品解释得更深 |
| 信息增益 | 20% | 是否提供了竞品没有的新价值 |
| 证据与 E-E-A-T | 15% | 是否有实测、来源、作者与测试方法 |
| 时效 | 5% | 时间、版本、事实是否当前 |
| 结构与体验 | 10% | 表格、层级、可读性与决策结构 |

所有单项先按 **0–100** 评分，再加权。

```text
摩天大楼得分
= 意图匹配 × 20%
+ 覆盖度   × 15%
+ 深度     × 15%
+ 信息增益 × 20%
+ 证据     × 15%
+ 时效     × 5%
+ 结构与体验 × 10%
```

## 状态分档

| 分数 | 状态 | 含义 |
| ---: | --- | --- |
| 80–100 | 强 | 该维度已是优势项 |
| 65–79 | 有竞争力 | 可用，但仍有明确改进空间 |
| 50–64 | 待改进 | 需要进入改造清单 |
| < 50 | 弱 | 优先处理 |

这是界面内部的阈值划分，不是搜索平台标准。

## 维度标准

| 维度 | 高分表现 | 常见失分 |
| --- | --- | --- |
| 意图匹配 | 页面类型、答案与结果页意图高度一致 | 用教程页去抢对比类关键词 |
| 覆盖度 | 核心问题、支撑问题、条件问题、下一步问题四层都覆盖 | 只答主问题，漏掉条件类追问 |
| 深度 | 从"是什么"推进到"为什么""怎么做""什么条件下成立""边界在哪" | 同一个结论换几种说法重复 |
| 信息增益 | 有原创数据、实测经验、新框架或原始证据 | 全是结果页已有的通识 |
| 证据与 E-E-A-T | 一手测试 + 署名 + 测试方法 + 一手来源 | 只有结论，没有口径 |
| 时效 | 时间、版本、价格、截图都是当前的 | 版本过期、事实已失效 |
| 结构与体验 | 直答、任务型小标题、对比表、决策矩阵 | 长段落、结论难找 |

### 覆盖度按四层检查

```text
核心问题 Core
支撑问题 Supporting
条件问题 Conditional
下一步问题 Next-step
```

**不按关键词数量评分**——堆词不等于覆盖。

### 深度看五层推进

```text
是什么 → 为什么 → 怎么做 → 什么条件下成立 → 边界在哪
```

### 信息增益分五类

| 类型 | 示例 |
| --- | --- |
| 数据型 | 原创基准测试 |
| 经验型 | 实际部署与调试记录 |
| 结构型 | 新框架、决策树 |
| 证据型 | 原始截图与日志 |
| 场景型 | 把参数映射到真实场景 |

### 证据与 E-E-A-T 检查项

经验、专业性、作者与审核者、一手来源、测试方法、主张—证据—边界是否齐备、来源时效。

### 时效检查项

更新时间、软件版本、产品状态、价格与可用性、截图、已失效事实。

### 结构与体验检查项

是否直答、小标题是否任务明确、是否有对比表与决策矩阵、段落密度、移动端可读性、关键结论是否容易找到。

> 所有得分都是**内部诊断模型**，不是任何搜索平台的官方排名分。
