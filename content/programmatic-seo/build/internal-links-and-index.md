> 程序化的两个技术问题：**页面之间要能被发现**（内链），**低价值页面不要占索引**（索引控制）。

## 内链的两种结构

**纵向：从聚合页到明细页**

```text
/rent/                全国总览，列出所有城市
  └ /rent/hangzhou/   城市页，列出该城市各板块
      └ /rent/hangzhou/xihu/   板块页
```

每一层都指向下一层，**明细页至少有一条来自上一层的入链**。

**横向：同类页面互相指**

城市页底部列相邻城市，板块页指同城其他板块。横向链接帮助爬虫发现新页面，也给用户顺路继续看的机会。

> 提示：程序化页面最容易出问题的地方是孤岛——生成几万页但没有任何内链指向它们，等于没生成。

## 索引控制

**不是所有生成的页面都该被收录**。判断标准：

| 情况 | 处理 |
| --- | --- |
| 有独立需求、有差异内容 | 正常收录 |
| 数据不足（字段大面积缺失） | 不生成，或生成但不索引 |
| 与其他页面高度重合 | 合并，或设置 `canonical` |
| 筛选/排序参数页 | 不索引，`canonical` 回主版本 |
| 分页第二页以后 | 正常收录，但别加 `canonical` 到第一页 |

工具用法：`noindex`、`canonical`、站点地图的取舍——三者的分工见抓取与索引控制。

## 站点地图要分组

几万个 URL 塞进一个 sitemap 会拖慢处理。做法：

- 按维度拆成多个 sitemap 文件，用索引文件串起来
- **只放要收录的页面**，`noindex` 的页面不要出现在里面
- 数据更新后重新生成，带上 `lastmod`

## 上线后看两个数

- **收录率**：GSC 里"已收录 / 已提交"的比例。低于一半说明页面价值不够
- **抓取分布**：日志里爬虫抓的是哪些目录。如果全在抓废页面，主力页面的抓取预算就被挤掉了

> 警告：**抓取预算是零和的**。生成的页面越多，分给每个页面的抓取次数越少。这是"索引爆炸"的技术成因，见下一节。
