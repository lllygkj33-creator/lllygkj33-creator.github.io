> 程序化 SEO 的质量上限由数据决定。**模板可以重写，数据不行。**

## 数据从哪来

按价值排序：

| 来源 | 价值 | 成本 |
| --- | --- | --- |
| 自己采集/实测 | 最高，别人抄不走 | 高 |
| 平台公开数据整理 | 中，需要加工和口径说明 | 中 |
| 用户产生（评价、投稿） | 高，且有本地性 | 中（要有人用） |
| 购买或抓取第三方 | 低，且不稳定 | 低 |

**优先用你独有的那一份**。哪怕只有几百行，也比抓来的几万行有用——因为那几百行没人能复制。

## 每行数据至少要有什么

```json
{
  "slug": "hangzhou-office-rent",
  "title": "杭州甲级写字楼租金行情",
  "updated": "2026-09-01",
  "fields": { "avg_rent": 4.2, "unit": "元/㎡/天", "sample": 86 },
  "diff": "样本来自本地中介的 86 条挂牌，含空置率"
}
```

三个字段不能省：

- **`updated`**：没有更新时间的页面，时效判断吃亏
- **样本量/口径**：数字必须能解释怎么来的
- **`diff`（差异点）**：这一行比其他行多什么。**这个字段为空的行，就是不该生成页面的行**

## 清洗标准

上线前把数据过一遍：

- [ ] 重复行合并（同一实体多个写法）
- [ ] 空值处理：关键字段为空的行直接排除，不要生成"暂无数据"的页面
- [ ] 单位统一，并在页面上标注
- [ ] 缺失比例超过 30% 的字段，不如不放

## 更新机制

程序化页面最大的优势是**数据更新即内容更新**，前提是更新真的发生：

1. 数据源确定采集频率（每周/每月）
2. 更新时自动改 `dateModified`
3. 数据变化大的页面，页面上的文字描述也要跟着调，不能只换数字

> 提示：把"数据更新"排进日常流程。三个月没更新的数据页，和一个没人维护的旧文章没有区别。
