一张卡片就是一个页面的观测结果：它写了哪几个实体、每个实体上写了什么、和标准知识比出来是什么状态。注意最后一行——不一致出现在页面内部，还没走到跨站比较就已经存在。

卡片上不写「谁对」。同样的内存值，状态写一致，只代表这个页面和当前的标准知识说法相同，不代表这个数字从此不会再变。

## 一个页面可以有 0 / 1 / N 个品牌实体

| 情况 | 例子 | 处理 |
| --- | --- | --- |
| 0 个品牌实体 | 讲 RAID 5 原理的科普页 | 跳过，不抽取、不进队列 |
| 1 个品牌实体 | 一个型号的产品页 | 正常记录，进入比较 |
| N 个品牌实体 | 同时讲多个型号的活动页 | 按实体拆开，各自独立判定 |
| 出现第三方产品 | 与树莓派对比的段落 | 只作上下文，不建完整记录 |

0 个不等于页面有问题，只说明它不属于这套治理范围。N 个也不等于要合并：同一个页面里的两个实体是两条观测，不共享结论。第三方产品只作为上下文保留，不建立标准记录，否则审核队列会失去焦点。

## 先对齐实体，再谈比较

抽出来的值不能直接拿去比，中间有两步不能跳过：先判断这是哪个实体，再写下这条说法覆盖哪个层级（型号 / 变体 / 套餐）。第一步错了后面全错——新出现的产品代际不能被硬对到旧代际上，商城已经在卖新一代产品而标准知识里只有上一代时，正确动作是标记为发现新实体，交人决定要不要新建。层级写错的代价同样具体：把型号级的 FAQ 当成某个 SKU 专用，会立刻报出一片假冲突。

对齐实体这一步只需要回答一个问题：这个页面在讲我们已有的哪个实体。答不上来时，宁可标成发现新实体，也不要硬塞进最像的那一个。

两条链路的分叉点在「谁来下结论」。错误链路默认页面是对的，所以错误会顺着引用扩散；正确链路里观测只负责发现差异，结论始终由人给出。

页面数量越多，这个分叉越关键：5000 个页面跑完，错误链路会得到一份没人能追溯来源的知识库，正确链路会得到一份带位置的待审清单。

## 红线：页面内容不能反向污染标准知识

<div class="bae-note" data-tone="warn"><b>单向是硬要求</b>：页面 → 观测 → 比较 → 人工审核；页面 → 观测 → 标准知识这条路径不存在。</div>

对 Blog 尤其要严：发布时可能正确，今天已经过期；写作目的是可读与说服，不是规格准确；措辞天然倾向把「可以运行」写成「最适合」。所以页面里抽出的内容只有两个去向——上报为待审项，或作为页面上下文保留。观测本身也不下结论：一致只表示和当前标准知识相同，不表示永久正确；需要确认只表示这里要人看一眼，不表示页面写错了。

页面措辞比标准知识更强时，动作同样只有一个：标成待审，不能顺手接受它。系统可以报告差异，不能替人把差异「洗白」成新结论。
