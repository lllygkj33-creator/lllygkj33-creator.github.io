> 要问的不是「哪个站点更可信」，而是「**这个字段**该信谁」。来源权威是字段级的：同一台机器，内存看规格页，当前价格看商城。

## 字段矩阵：权威按字段分配

| 字段类型 | 权威来源 | 本轮的例子 |
| --- | --- | --- |
| CPU / 内存 | 规格页 / Manual | 8GB LPDDR5 4800MHz |
| 价格 / 库存 | 商城 PDP | 在售 SKU 与 Bundle 构成 |
| ZimaOS 功能 | Docs / Release Notes | 当前已提供的能力 |
| 使用场景 | 品牌主张 | 适合 Home Server |
| 实测性能 | 一方测试 | 转码与吞吐结论 |

这张表要横着读：一行一个字段，没有哪一列能整行通吃。规格字段换到商城去问，拿回来的是营销措辞；交易字段换到品牌页面去问，拿回来的是上一季的答案。

反过来说，每个来源也都有它不该定的事。品牌页面不定当前价格与库存，商城不定长期硬件规格与产品定位，开发者文档不定硬件参数，社区与用户内容只算经验证据，永远不直接产生标准知识。

## 「www > shop」这种排法不成立

<div class="bae-note" data-tone="warn"><b>不要给站点排总序</b>：<b>www &gt; shop</b> 这类域名级结论，在第一个交易字段上就会失效。</div>

商城 PDP 是 SKU、Bundle、价格与库存的实时来源，品牌产品页通常只描述型号，不知道今天在卖哪几个套餐。反过来，产品定位与硬件规格只有品牌站在持续维护，商城的营销段落不该被当成长期规格的判据。权威属于字段，不属于域名。

前三步都能按规则走，只有最后一步例外：来源再权威，也不允许系统替人合并两个说法。落到一条具体记录上，还要记住权威是「来源 + 位置」的组合：同一个规格页的规格表和它的客服问答，可信度并不一样。

## 一个例子：内存和当前价格

内存 8GB LPDDR5 4800MHz 写在品牌规格页的规格表里，描述的是 832 这个变体的固定硬件，商城不该覆盖它。当前价格与库存随活动变动，只能以商城 PDP 为准，品牌产品页上的说法随时可能是上一季的。ZimaOS+ 的 29 USD 属于权益价格，权威在 Pricing 页，既不在商城 PDP 上，也不在产品页上。

## 边界一：同一来源内部自相矛盾

来源排得再高，也不保证它自己前后一致，这类问题不用跨站比较就能发现。商城 PDP 的规格区写预装 ZimaOS Plus，同一页的 FAQ 却写 ZimaOS；同样的形态在几个官方页面上都出现过。正确动作是单独标记、单独进审核，而不是按「来源更高」直接选一个。

| 同一来源内的两条记录 | 待确认的问题 |
| --- | --- |
| 商城规格区：ZimaOS Plus / 商城 FAQ：ZimaOS | 预装镜像是哪个，Plus 是镜像、版本还是权益 |
| 规格页把 Unraid 列为兼容系统 / 同站 FAQ 说仍在测试 | 当前兼容状态到底是哪一个 |
| 概览写容量最高 36TB / 同站 FAQ 说 SATA 再加 20TB | 这是总容量还是新增容量 |

## 边界二：旧内容不等于写错

历史内容记的是当时正确的事，不能一律标成冲突。旧活动文章里的说法只与它那个时代的记录一致时，正确动作是标记为**可能已经过期**（stale_candidate），让审核者先问一句「它当时对不对」。时间敏感文案同理：产品页还留着 Backup「未来上线」的说明，而当前 ZimaOS 页已经把 Backup 当作可用功能提供，该改的是过时措辞，不是某个数字。

来源越权威，越要记住它也有时效：规格页会改版、Pricing 会调价、Release Notes 会推进状态。判断顺序固定为「字段定来源 → 来源查同源矛盾 → 时效决定状态 → 不一致交人」。
