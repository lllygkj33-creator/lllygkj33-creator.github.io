> 全量扫描是一次性动作，增量才是长期运行方式：页面要不要重抽，只看**内容指纹**变没变。

## 一次全量，之后每天只处理变化

第一轮必须把 5000 页扫完，之后每天要看的是"今天有几页真的变了"。

抽取是整个流程里最贵的一步，成本从"与页面总数成正比"降到"与当天变化数成正比"，才谈得上每天跑一轮。

增量本身不产出新知识，它只决定这一轮把预算花在哪几十页上。

## 怎么判断哪些页面要重抽

判断几乎全部落在内容指纹上，另外两条只负责"改了什么就修什么"。

| 情况 | 处理方式 |
| --- | --- |
| 内容指纹变了 | 重新抽取，结果当新的页面观测 |
| 指纹没变，但标准知识改了 | 走依赖追踪反查受影响页面，不重抽 |
| 指纹没变，但模板版本变了 | 只重跑结构解析，不调用抽取 |
| 指纹和模板都没变 | 跳过，只记一次最近出现时间 |

指纹应该只算在清理后的正文上，不算整个 HTML，否则站群换一次页脚就会让 5000 页同时"变化"。

一轮跑起来大致是这样：

  <div class="bae-node" data-tone="canonical"><b>与标准知识比对</b><span>一致 / 冲突 / 范围不一致，进审核</span></div>
  <div class="bae-caption">知识侧的变化另走依赖追踪，不重新抓页面</div>
</div>

模板改版往往先让一批页面的指纹一起变化，这时候先看正文比对结果，再决定这批页面要不要重新抽取。

反查出来的页面只是**候选受影响集合**，不是冲突清单：页面引用了同一条知识，不等于它已经和新的标准答案矛盾。

判断仍然要按比对规则做，不能因为出现在受影响列表里就标成冲突。

## 每轮得记住什么

要让下一次比对成立，每条页面记录至少得留住三个值：

```json
{ "url": "/blog/zimaboard-2-local-ai-assistant",
  "content_hash": "a41f…", "template_version": "v3",
  "canonical_ids": ["F_ZB2_832_RAM", "C_ZB2_MININAS"] }
```

指纹回答"内容变了吗"，模板版本回答"外壳换了吗"，依赖列表回答"知识变了要回头核对谁"。

这三个值都只服务于判断，不用来展示；页面上给人看的仍然是实际值、来源和状态。

## 跳过的页面不等于安全

跳过只说明"这轮不用重新抽内容"，不代表这个页面已经没有问题。

被跳过的页面照样进抽样池、照样被依赖反查命中，还要看它的时效：长期没变化本身就是一个信号，可能已经过期，也可能已经下架。

## 抽样 QA 真正在防什么

它的目的不是省钱，恰恰相反，它要多花钱：指纹没变而语义已经错了，只能靠主动重核发现。

所以抽样池必须包含本轮跳过的页面，否则只能验证"变化有没有被正确处理"，验证不了知识本身还对不对。

新页面和上轮抽取失败的页面也一律重跑，它们与指纹无关。

## 时间戳只是提示

<div class="bae-note" data-tone="warn"><b>容易误判</b>：<code>last_modified</code> 只能当提示，不能当证据——页面改了却没更新时间、没改却刷新时间，两种都很常见。</div>

一篇旧 Blog 可能永远不变化却早就过期，那是陈旧问题，指纹永远不会暴露它。

增量还有它自己看不见的地方：新上线的页面和以前漏抓的页面都不会进入指纹比对，所以隔一段时间仍要重跑一次全量。

指纹的基准本身也要按版本保存，基线被覆盖掉之后，这一轮的变化就再也算不出来了。
