> 所有判定都是**内部规则**，用来定位可修的问题，不是任何搜索平台的标准。规则写清楚的好处是：同一份数据换个人看，结论一致。

## 孤岛

```text
incoming_count = 0  →  is_orphan = true
```

需要排除不参与图谱的系统页面：归档页、标签页、分类页、特殊落地页。

> 这里的孤岛只表示**在 Blog 内部链接图谱里没有入链**。页面可能仍然通过站点地图、分类页、导航或外链被发现。界面上写"图谱孤岛"，不写"搜索引擎孤岛"。

## 死胡同

```text
outgoing_count = 0  →  is_dead_end = true
```

本身不一定是问题。但两种情况值得处理：

- **高流量页面 0 出链**：通常意味着有现成的内链机会没做
- **同一主题簇内多个死胡同**：会让这一簇内容变成封闭的孤块，簇外的页面进不来，簇内的价值出不去

## 弱连接

```text
incoming_count ≤ 1  →  is_weak = true
```

阈值可配置（`weak_incoming_threshold`，默认 1）。孤岛与弱连接分开呈现：前者是完全没有，后者是有但只有一条。

## 断链

```text
target_status ∈ {404, 410, 5xx}  →  broken = true
```

这一类是**最直接可执行的修复列表**：来源、锚文本、目标、状态四列就能派工。

## 重定向

```text
target_status ∈ {301, 302}  →  记录 final_url
```

它说明的问题是：**正文还在链旧地址**。跳转虽然有效，但每次点击都多一跳，而且旧地址的权重传导不如最终地址直接。处理方式是把正文里的链接改成最终地址。

## 自链

```text
source = target  →  不计入图，单独记入自链清单
```

自链通常来自模板或复制粘贴。数量异常时，说明模板层有需要修的地方。

## 重复链接

同一来源对同一目标的多次链接：

- 入链数**只算 1 条**，避免虚高
- 边保留 `occurrences` 与全部锚文本
- 图谱用虚线区分"这条边有重复"

## 锚文本分析

每条边都保留锚文本，后续可分类：

| 类型 | 例子 | 说明 |
| --- | --- | --- |
| 空锚文本 | 无文字 | 需要补 |
| 通用锚文本 | read more、点击这里 | 不传递主题信息 |
| 精确重复 | 同一目标全站用同一个锚文本 | 自然度下降 |
| 品牌锚文本 | 品牌名 | 用于品牌页 |
| 主题锚文本 | Plex 硬件要求 | 最理想 |
| 主张锚文本 | 实测 12 款的转码结果 | 信息量最高 |

第一版只做**保留与呈现**，不自动生成、不自动改写锚文本。

## 主题与簇

如果站点已有分类、标签或内容簇数据，直接同步进节点：

```json
{ "topic": "home-server", "cluster": "plex" }
```

**不要让模型猜主题并直接写进主数据**。没有可靠来源时，猜测结果单独放在 `inferred_topic` 字段，供人工确认后再合并。

有了主题数据，图谱就能回答两类结构问题：

- **簇内连接是否充分**：某一簇内部互相链接够不够
- **簇间是否存在桥接**：两个相关主题之间有没有页面把它们连起来

本次示例里 Plex 与 NAS 之间就存在一条跨簇桥接——这类页面是把两组内容连成网络的关键。

## 优先级（第二阶段）

```text
孤岛优先级 = 流量价值 × 主题重要度 × 链接缺口
```

必须标注为**内部优先级模型**，不是平台排名公式。第一版按 `incoming_count` 升序排序即可。

## 不混入的指标

第一版只用结构指标：

```text
入链 / 出链 / 孤岛 / 死胡同 / 断链 / 重定向 / 主题 / 锚文本
```

不混入外部权重指标（域名评分、搜索量一类）。结构问题用结构数据解决，混入外部指标只会让优先级判断变模糊。第二阶段如果要排序，再引入搜索表现数据。
