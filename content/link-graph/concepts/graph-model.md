> 图谱只有两种东西：**节点**和**边**。状态不是存下来的，是从入链和出链算出来的。

## 节点与边

```text
一篇 Blog  =  一个节点
一条内链   =  一条有向边
```

边的方向就是链接方向：`来源 → 目标`。入链是别人指向我，出链是我指向别人。

## 四种节点状态

| 状态 | 判定 | 含义 |
| --- | --- | --- |
| Hub | 入链 ≥ 3 | 被大量页面支持的枢纽 |
| 健康 | 入链 ≥ 2，且有出链 | 参与主题关系 |
| 弱连接 | 入链 = 1 | 只有一条路径能到达 |
| 孤岛 | 入链 = 0 | 图谱内没有任何页面指向它 |
| 死胡同 | 出链 = 0 | 不指向任何其他页面 |

后两个是独立维度，可能同时成立：一个页面可以既是孤岛又是死胡同。

## 跨簇桥接

主题簇内部的链接只能证明簇内自洽；**把两个簇连起来的那条边才是网络结构的关键**。

图上用蓝色实线标出跨簇边。示例里有三条：NAS → Plex、Local AI → Plex、Media → Plex。它们说明 Plex 簇同时被三个相邻主题引用，是整个站的内链重心。

如果两个相关主题之间**完全没有跨簇边**，那它们实际上是两个孤立的岛，即使各自内部连接再密。

## 邻接矩阵：同一份数据的另一种看法

图适合看结构，矩阵适合看细节。**邻接矩阵的行是来源，列是目标，格子表示"这一行有没有链接到这一列"。**

读法：

```text
行 = 来源页面
列 = 目标页面
格子里有 ● = 存在一条内链
对角线留空   = 自链不计入图谱
```

两种视角各有所长：

| | 图谱 | 邻接矩阵 |
| --- | --- | --- |
| 擅长 | 结构、簇、桥接、视觉直觉 | 精确关系、稀疏程度、逐行核查 |
| 不擅长 | 精确计数、大站可读性 | 一眼看出簇与形状 |
| 大站表现 | 节点过密后不可读 | 仍然可读，但表格变宽 |

矩阵里能直接看出的问题：

- **整行为空**：这个页面没有出链，是死胡同
- **整列为空**：没有页面指向它，是孤岛
- **同一格出现多次**：重复链接，图谱里合并为一条边
- **对角线附近密集**：链接集中在小圈子里，缺少跨簇连接

## 为什么状态要算而不是存

同一个页面，明天可能从弱连接变成健康——只要有人加一条内链。所以状态**每次抓取重新计算**，不写死在数据里。JSON 里保存的 `is_orphan` 这类字段是当次计算的结果，不是永久属性。

换句话说：**图是数据算出来的，不是人画出来的。** 数据一变，图、矩阵、统计卡一起变，三者永远一致。
