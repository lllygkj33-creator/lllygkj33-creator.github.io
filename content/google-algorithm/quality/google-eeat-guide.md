> E-E-A-T 的核心不是“给页面加作者头像”，而是：**让用户和搜索系统有足够理由相信这篇内容由合适的人、以合适的方法、在可验证的证据基础上完成。**

需要先纠正一个常见误区：E-E-A-T 不是一个可以单独计算的 Google 排名分数，也不是一个名为“E-E-A-T Algorithm”的独立算法。Google 公开说明，自动排名系统会综合许多信号去识别具有良好 E-E-A-T 特征的内容，而质量评分员使用 E-E-A-T 框架评估搜索结果质量；评分员本身不会直接调整某个页面的排名。

## 四个维度

| 维度 | 核心问题 | 常见证据 |
| --- | --- | --- |
| Experience | 你是否真的做过、用过、经历过 | 实拍、测试记录、第一手案例、过程截图 |
| Expertise | 你是否具备完成判断所需的知识和技能 | 专业经历、方法说明、技术深度、资格 |
| Authoritativeness | 你是否被这个领域视为可靠来源 | 行业引用、品牌提及、专家引用、长期主题积累 |
| Trust | 这条信息是否准确、安全、诚实、可靠 | 来源、作者、利益披露、联系方式、更新记录 |

其中 **Trust 是中心**。

一个人可能有很强 Experience，但结论夸张、数据不可验证，Trust 仍然不足。

一个作者也可能没有亲自体验某种疾病，但作为专业医生具备更高 Expertise，因此更适合解释医疗问题。

## Experience

Experience 强调第一手经历。

例如产品评测：

| 弱信号 | 强信号 |
| --- | --- |
| 重写官网规格 | 实际使用产品 |
| 使用厂商图片 | 自己拍摄测试图 |
| “感觉很快” | 给出测试环境和结果 |
| 汇总他人评论 | 说明自己使用了多久 |
| 没有失败记录 | 同时记录优点、限制和异常 |

例如写：

```text
This monitor has excellent motion clarity.
```

很弱。

更强的是：

```text
We tested the monitor at 240Hz using DisplayPort with the same GPU,
game scene and overdrive setting used for the 144Hz comparison.
```

这里同时提供：

```text
谁测试
怎么测试
测试条件
比较基线
```

## Expertise

Expertise 不是“头衔越高级越好”。

关键是：

> **作者的知识是否和当前主题匹配。**

| 内容 | 更合理的 Expertise |
| --- | --- |
| 显示器评测 | 长期硬件测试经验 |
| Docker 教程 | 实际部署和运维经验 |
| 家庭理财 | 合格金融专业人士或严谨编辑体系 |
| 电路维修 | 电工专业知识 |
| 医疗治疗建议 | 医疗专业资格 |
| 用户旅行体验 | 实际去过当地的人也可以很有价值 |

对于非 YMYL 主题，长期爱好者的深度实践经验可能足够。

对于 YMYL，专业要求明显更高。

## Authoritativeness

Authority 更接近：

> **别人是否把你当作这个主题的参考来源。**

它通常不是靠页面自己声明产生的。

可以从这些地方观察：

- 其他网站是否引用你
- 行业媒体是否提到你
- 作者是否长期写同一主题
- 品牌是否有稳定专业定位
- 是否存在独立评价
- 是否被社区当成参考资料
- 是否有原创研究、工具或数据被引用

例如：

```text
网站有 300 篇互不相关内容
```

不一定比：

```text
网站有 80 篇长期围绕显示器技术的深度内容
```

更有主题权威。

## Trust

Trust 是最后的总判断。

可以拆成：

| 信任维度 | 检查 |
| --- | --- |
| 准确 | 事实是否可核验 |
| 诚实 | 是否夸大、隐藏限制 |
| 安全 | 建议是否可能伤害用户 |
| 透明 | 谁写、怎么写、谁负责 |
| 商业关系 | 是否披露 Affiliate / Sponsor |
| 更新 | 过时信息是否及时修正 |
| 网站主体 | 公司、联系方式、政策是否真实 |

电商站的 Trust 还包括：

- HTTPS
- 明确价格
- 配送政策
- 退换政策
- 客服方式
- 公司主体
- 支付安全
- 产品信息一致

所以 Trust 不只是文章正文问题。

## 谁、怎么做、为什么

Google 的 People-first 指南很适合用三个问题检查 E-E-A-T：

| 问题 | 要验证什么 |
| --- | --- |
| Who | 谁创建了内容 |
| How | 内容是怎么产生的 |
| Why | 为什么要创建它 |

### Who

页面应该尽量明确：

```text
作者是谁
作者负责什么主题
作者页在哪里
有没有真实经历
是否经过审阅
```

### How

尤其是测试、排行、评测内容，要说明：

```text
测试多少产品
测试条件
数据怎么得到
图片是不是实拍
有没有使用 AI
如何核实事实
```

### Why

最关键的问题是：

> 这篇内容首先是为了帮助用户，还是只是为了获取搜索流量？

如果内容唯一目的就是捕捉热门词，且站点本身没有对应受众、经验和价值，风险会明显增加。

## 页面级检查

可以使用下面这张表做 Page QA。

| 项目 | 通过标准 |
| --- | --- |
| 主作者 | 明确可识别 |
| 作者页 | 有真实背景和主题范围 |
| 第一手经验 | 该类型内容需要时存在 |
| 原始证据 | 重要 Claim 可验证 |
| 来源 | 优先原始或权威来源 |
| 商业关系 | 明确披露 |
| 更新时间 | 重要事实保持当前 |
| 限制 | 不把条件性结论写成绝对事实 |
| About / Contact | 网站主体可验证 |
| 审阅 | 高风险主题有匹配审阅者 |

## 站点级检查

E-E-A-T 不应该只做在单页。

| 站点信号 | 检查方法 |
| --- | --- |
| 主题范围 | 网站是否有稳定核心主题 |
| 作者网络 | 每个作者是否有明确专业领域 |
| 实体一致 | 品牌名、作者、公司信息是否一致 |
| 外部声誉 | 搜索品牌、作者和第三方评价 |
| 原创资产 | 是否有测试、数据、图片、工具 |
| 内容治理 | 是否更新、纠错、合并过时内容 |
| 编辑政策 | 是否说明测试、审阅、AI 使用原则 |

## 常见行业要求

| 行业 / 品类 | 更关键的 E-E-A-T | 红线 |
| --- | --- | --- |
| 普通消费电子 | Experience + Trust | 假装实测、伪造数据 |
| 医疗健康 | Expertise + Trust | 无专业依据给诊断或治疗承诺 |
| 金融投资 | Expertise + Trust | 保证收益、隐藏风险 |
| 法律 | Expertise + Trust | 把一般信息写成确定法律结论 |
| 安全 / 电气 | Expertise + Trust | 提供危险操作却没有边界 |
| 软件教程 | Experience + Expertise | 未验证命令、版本过时 |
| 产品评测 | Experience + Trust | 未使用产品却写“hands-on” |
| 新闻 / 趋势 | Authority + Trust | 无来源传播未经证实消息 |

## 高风险红线

以下行为会直接破坏 Trust：

| 行为 | 问题 |
| --- | --- |
| 虚构作者 | 身份不可验证 |
| AI 假头像冒充真人 | 欺骗 |
| 伪造学历 / 资格 | 欺骗 |
| 抄写第三方实测 | 假 Experience |
| 商业稿不披露 | 利益关系不透明 |
| 修改日期伪装更新 | Freshness 欺骗 |
| 用 1 个案例推出行业结论 | 证据不足 |
| 无来源给高风险建议 | YMYL 风险高 |

## 一个内部评分模型

这不是 Google 官方算法，只适合内容 QA。

```text
E-E-A-T QA
=
Experience 20%
+
Expertise 25%
+
Authority 20%
+
Trust 35%
```

为什么 Trust 权重最高？

因为 Experience、Expertise、Authority 最终都应该服务：

```text
这条信息是否值得相信
```

可以按 0–5 分评分。

| 得分 | 判断 |
| ---: | --- |
| 4.5–5.0 | 很强 |
| 3.5–4.4 | 合格 |
| 2.5–3.4 | 需要补证据 |
| <2.5 | 不建议直接发布高风险结论 |

## 怎么检测

### 站内检索

检查：

```text
site:xxxx.com "作者名"
site:xxxx.com "主题词"
```

确认作者是否长期和目标主题绑定。

### 品牌检索

搜索：

```text
品牌名
品牌名 reviews
作者名
作者名 + 专业主题
```

观察第三方世界里是否存在对应实体。

### 内容抽样

随机抽 20 篇文章，记录：

| 检查 | 数量 |
| --- | ---: |
| 有明确作者 | ? |
| 有原始来源 | ? |
| 有第一手证据 | ? |
| 有审阅者 | ? |
| 有明显过时事实 | ? |
| 有未经支持 Claim | ? |

问题如果是系统性的，就不要只修一篇文章。

## 核心优化目标

E-E-A-T 最终不是为了“加几个元素”。

真正的目标是：

```text
作者身份真实
+
专业范围清楚
+
内容生产过程透明
+
重要结论有证据
+
网站在对应主题长期积累
+
用户可以验证和追责
```

> **E-E-A-T 的优化对象不是一个 Meta 标签，而是整套内容可信度。Experience 证明你做过，Expertise 证明你懂，Authority 证明别人认可，Trust 决定用户和搜索系统最终是否应该相信你。**
