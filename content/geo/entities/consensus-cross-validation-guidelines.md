> 共识不是“很多网页都这么说”，而是：**多个独立、可靠、条件一致的证据最终指向同一个结论。**

## 什么是共识

例如三个来源都写：

```text
Product X supports 4K 120Hz.
```

需要进一步问：

```text
它们是不是都引用同一个官方规格？
```

如果是：

```text
3 个页面
=
1 个原始证据
```

真正的共识需要更强独立性。

## 交叉验证

标准流程：

```text
Claim
→
Source A
→
Source B
→
Source C
→
检查独立性
→
检查条件
→
判断是否一致
```

## 来源独立性

| 情况 | 独立性 |
| --- | --- |
| 官方规格 + 独立测试 | 高 |
| 两个独立实验室 | 高 |
| 三家媒体都引用官方稿 | 低 |
| Reddit 三个不同用户 | 中 |
| 同一作者多平台转载 | 低 |

数量不能代替独立性。

## 条件必须一致

两个 Benchmark 不同，不一定冲突。

例如：

| 测试 | Model A |
| --- | ---: |
| 4-bit, 4K context | 38 tok/s |
| 8-bit, 32K context | 19 tok/s |

条件不同，所以不能直接比较。

交叉验证前应统一：

- Version
- Hardware
- Quantization
- Context
- Dataset
- Date

## 父边与子边

复杂结论可以通过多条子边支持。

父边：

```text
240Hz
→ improves competitive responsiveness
```

子边：

| 子边 | 证据 |
| --- | --- |
| 240Hz → 4.2ms interval | 数学 |
| 4.2ms → more refresh opportunities | 机制 |
| Competitive FPS → latency-sensitive | 场景 |

这比直接找一句：

```text
240Hz is better
```

更强。

## 多路径验证

假设父关系：

```text
A → B
```

存在：

```text
A → C → B
A → D → B
A → E → B
```

如果 C、D、E 来自不同机制和独立来源，父边可信度提高。

这可以理解为：

```text
多条独立路径
→
共同支持父结论
```

## 共识不是多数投票

如果：

```text
9 个普通博客
```

和：

```text
1 个官方标准
```

发生冲突，不应该机械按：

```text
9 > 1
```

判断。

应该看：

```text
Evidence Quality
```

而不是数量。

## 冲突处理

| 冲突原因 | 动作 |
| --- | --- |
| 版本不同 | 分版本写 |
| 时间不同 | 使用最新有效事实 |
| 地区不同 | 标明地区 |
| 测试条件不同 | 不直接比较 |
| 来源等级不同 | 提高高等级证据权重 |
| 无法解决 | 明确存在争议 |

不要隐藏冲突。

## 共识强度

内部可以定义：

```text
Consensus Strength
=
Evidence Quality
+
Source Independence
+
Condition Alignment
+
Result Consistency
```

每项 1–5。

不是搜索引擎官方算法，只用于 QA。

## 用户经验

UGC 共识也有价值，但适合证明：

```text
常见体验
```

不适合单独证明：

```text
科学事实
医疗结论
技术标准
```

例如：

```text
10 个用户都说风扇很吵
```

可以说明：

```text
存在较强主观体验信号
```

但不能直接等于精确：

```text
50 dBA
```

## GEO 为什么需要共识

生成式系统需要降低：

```text
单一错误来源
```

导致的回答风险。

所以高价值内容应尽量做到：

```text
基础事实
→
与可靠共识一致

原创价值
→
在共识基础上增加
```

不要为了 Information Gain 故意反常识。

## QA 表

| 检查 | 合格 |
| --- | --- |
| 原始来源已追溯 | 是 |
| 来源独立 | 是 |
| 版本一致 | 是 |
| 条件一致 | 是 |
| 冲突已解释 | 是 |
| 数量不代替质量 | 是 |
| 高风险 Claim 多源验证 | 是 |

## 核心规范

```text
找 Claim
→
追原始来源
→
确认独立性
→
统一条件
→
比较结果
→
形成共识或明确争议
```

> **交叉验证的目标不是找到更多支持自己的页面，而是验证一条关系在不同独立证据路径下是否仍然成立。**
