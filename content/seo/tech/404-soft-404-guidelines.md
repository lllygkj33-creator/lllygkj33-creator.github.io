> 404 本身不是 SEO 灾难。真正的问题是：**重要页面无故消失、失效 URL 大量产生，或者不存在的页面却返回 200，让搜索引擎无法判断资源状态。**

## 404 是什么

HTTP 404 表示：

```text
页面不存在
```

常见原因：

- URL 拼错
- 页面删除
- 产品下架
- Slug 修改
- 外部链接错误
- 路由异常

正常网站出现少量 404 很常见。

## 404 会不会处罚网站

不会因为存在几个 404 就触发所谓“Google Penalty”。

真正需要处理的是：

| 情况 | 风险 |
| --- | --- |
| 核心页面突然 404 | 高 |
| 大量内链指向 404 | 高 |
| Sitemap 有大量 404 | 高 |
| 外链强页面 404 | 高 |
| 少量随机错误 URL | 低 |

所以重点是：

```text
404 的来源和价值
```

## Soft 404 是什么

Soft 404 指页面实际上不存在或没有有效内容，但服务器返回：

```text
200 OK
```

例如：

```text
Product not found
```

页面却返回 200。

或者：

```text
页面只有“没有内容”
```

但仍然标记正常页面。

搜索引擎可能自行判断为：

```text
Soft 404
```

## 常见 Soft 404

| 情况 | 例子 |
| --- | --- |
| 空产品页 | Product unavailable |
| 空分类页 | 0 Products |
| 自定义错误页返回 200 | Not Found |
| 极薄内容 | 没有实质主内容 |
| 错误重定向 | 所有旧页跳首页 |
| 地区不可用 | 页面无内容但 200 |

## 404 和 410

| 状态码 | 含义 |
| --- | --- |
| 404 | 当前找不到 |
| 410 | 明确永久删除 |

对于永久删除且没有替代的内容：

```text
410
```

可以更明确表达：

```text
Gone
```

但普通 404 也完全正常。

不需要为了 SEO 强迫所有删除页都用 410。

## 什么情况 301

如果旧页面有高度相关替代：

```text
Old Product
→
New Product Version
```

可以：

```text
301
```

如果：

```text
Old Guide
→
Merged Guide
```

也适合：

```text
301
```

关键是：

```text
目标必须相关
```

## 什么情况保留 404

如果：

```text
页面不存在
没有合理替代
```

最正确的就是：

```text
404
```

不要：

```text
所有 404
→ Homepage
```

这种做法可能被视为 Soft 404，也会让用户困惑。

## 产品下架

电商最常见。

| 情况 | 处理 |
| --- | --- |
| 临时缺货 | 保留 200 |
| 很快补货 | 保留产品页 |
| 永久停售但有替代 | 301 到替代产品 |
| 永久停售但有历史需求 | 可保留历史页 |
| 永久删除无价值 | 404 / 410 |

临时缺货不应该直接 404。

## 有外链的 404

如果失效 URL 有高质量外链：

```text
不要直接丢掉
```

先检查是否有最相关新页面。

例如：

```text
旧研究报告
→
新版研究报告
```

可以 301。

但不要为了“保权重”：

```text
任何旧 URL
→ Homepage
```

## 404 页面 UX

自定义 404 应该：

- 明确告诉用户页面不存在
- 提供搜索
- 提供导航
- 推荐相关内容
- 保持品牌风格

但 HTTP 状态仍然应该是：

```text
404
```

漂亮的错误页不能返回 200。

## GSC 怎么看

Search Console 中可能看到：

- Not found (404)
- Soft 404
- Redirect error
- Crawled - currently not indexed

处理时先判断：

```text
这个 URL 本来应该存在吗？
```

### 应该存在

修复页面或路由。

### 不应该存在

确认：

```text
404 / 410 正常
```

即可。

不是所有 GSC 404 都必须“修成绿色”。

## 大量 404 的来源

| 来源 | 处理 |
| --- | --- |
| 内链错误 | 修复 |
| Sitemap 错误 | 删除 |
| 旧 URL 迁移 | 301 |
| Bot 随机请求 | 可忽略 |
| 参数生成 | 修 URL 规则 |
| 外链拼错 | 有价值时重定向 |

## Soft 404 排查

检查：

| 项目 | 异常 |
| --- | --- |
| HTTP Status | 200 |
| Main Content | 空 |
| Title | Not Found |
| Product | 不存在 |
| Search Result | 0 Results |
| Redirect | Homepage |

如果页面实际无价值，应返回真实状态或提供有价值内容。

## 修复后的检查

| 项目 | 目标 |
| --- | --- |
| Broken Internal Links | 0 或极低 |
| Sitemap 404 | 0 |
| Canonical 404 | 0 |
| Redirect Target | 200 |
| Soft 404 | 持续下降 |
| High-value Backlink 404 | 已处理 |

## 常见误区

| 误区 | 问题 |
| --- | --- |
| 所有 404 都要 301 | 会制造无关跳转 |
| 404 会处罚全站 | 不是这样 |
| 自定义 404 返回 200 | Soft 404 |
| 缺货直接 404 | 错失用户和历史信号 |
| GSC 有 404 就必须清零 | 不必要 |
| 所有失效页跳首页 | 可能 Soft 404 |

## 核心规范

```text
页面该存在
→ 修复

页面永久迁移
→ 301

页面永久删除无替代
→ 404 / 410

页面不存在却返回 200
→ 修 Soft 404
```

> **正确的 404 是网站健康的一部分。失效页面治理的目标不是“零 404”，而是让每个 URL 的 HTTP 状态和真实内容状态保持一致。**
